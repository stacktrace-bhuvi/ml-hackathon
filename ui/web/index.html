01 · The problem

GPS lies a little. Roads don't.

Tall buildings, trees and signal loss push GPS points 5–30 m away from the true position — onto parallel streets, across buildings, or into gaps.

Noisy observations

.track — longitude, latitude and time, about one point per second, with jitter, drift and dropouts.

Road network graph

.nodes are junctions, .arcs are directed road segments between them — from 900 to 300 000 per trip.

Reconstructed route

One road segment per GPS point, chained into a route that is both likely and physically connected.

02 · The pipeline

From dots to a driveable route

  1. 1

    Project to metres

    Each trip uses its own UTM zone, so distances like “point → road = 12 m” are real metres anywhere on Earth.

  2. 2

    Candidate roads

    A spatial index (STR-tree) shortlists road segments near every GPS point.

  3. 3

    Feature engineering

    Distance, heading difference, speed, rank, arc length and connectivity describe each candidate.

  4. 4

    Classifier

    Seven models from seven algorithm families compared with trip-grouped cross-validation; LightGBM selected and tuned with Bayesian optimisation (Optuna TPE). Outputs P(correct road).

  5. 5

    HMM + Viterbi

    Emission = classifier probability; transition = driving distance on the directed road graph vs straight-line GPS distance. Viterbi finds the best connected chain; shortest paths fill the gaps between matched roads.

  6. 6

    Score on the server

    The API compares against the reference route on Laptop 1 only — ground truth never reaches this page.
